# card_editor — 紙のケースマップを作るための配置エディタ

A0×2枚の紙面に、88ケースの「カード」とタグを並べたネットワーク図を作る。
最終成果物は物理的な印刷物。このディレクトリはその**配置を人が決めるための道具**で、
出力は「どのケースをどこに何mmで置くか」という座標データ（`layout_manual.json`）。

対象は `tag_review/out/tag_review.csv` の88件（音信不通7件を除く。アーカイブ38 / 進行中50）。
タグ割合は `plan05/results/soft_tags.json`、タグ色は `plan_final_report/make_report.py` と同じ対応。

## 使い方

```sh
.venv/bin/python card_editor/s1_fetch_thumbs.py      # サムネイル88枚を取得（初回のみ）
.venv/bin/python card_editor/s2_make_cards.py --proof # カード画像 + A4実寸テスト
.venv/bin/python card_editor/s3_build_editor.py      # out/editor.html を生成
```

`out/editor.html` は**単一ファイル**（約2MB）。カード画像をbase64で埋め込んでいるので、
相手にはこのファイルだけ渡せばよい。ダブルクリックしてブラウザで開くだけで、
サーバもインストールも解凍も不要。作業後は「保存(JSON)」で `layout_manual.json` が
ダウンロードされるので、それを送り返してもらう。

`data:` URI にしているのはサイズ都合ではなく、Canvasを汚染させないため。
画像を別フォルダに置いて `file://` で開くと `toDataURL()` が
セキュリティエラーになり、PNG書き出しが動かなくなる。

## リンクで渡す

**https://shio-koji.github.io/case_clustering/**

```sh
./card_editor/deploy_pages.sh    # s3 を回したあとに実行すれば同じURLで中身が入れ替わる
```

`gh-pages` ブランチに `index.html`（＝エディタ）と `.nojekyll`、`robots.txt` の3つだけを置いて
Pages で配信している。デプロイは git の低レベルコマンドでコミットを直接組む方式なので、
作業ツリーもHEADも触らない。

無料プランではプライベートリポジトリで Pages が使えないため、
この設定にあたって `case_clustering` を公開リポジトリに切り替えている。
権利の確認が済むまでの措置として、HTMLに `noindex` を、Pages に `robots.txt` を置いて
検索インデックスは抑止してある（アクセス制限ではない。URLを知れば誰でも開ける）。

**`tag_review/` と `card_editor/` は追跡していないので公開されていない。**
`tag_review/shiina_list.tsv` などは内部資料なので、`git add .` で巻き込まないよう注意。

エディタには「テキストで受け渡し」ボタンがある。リンク共有先が枠の中でページを開く場合
（claude.ai の Artifact など）はダウンロードとファイル選択が塞がれることがあるため、
配置データを本文としてコピー／貼り付けできる経路を用意してある。
枠の中かどうかを検出して説明文が切り替わる。

## ファイル

| | |
|---|---|
| `s1_fetch_thumbs.py` | CALL4のサムネイルをDL・縮小して `cache/thumbs/` に置く |
| `s2_make_cards.py` | カード画像を生成（版下 / プレビュー / A4実寸テスト） |
| `s3_build_editor.py` | 単一HTMLのエディタを生成 |
| `out/cards/*.jpg` | 版下 90mm角 @300dpi。実寸の試し刷り用 |
| `out/cards_preview/*.webp` | エディタ埋め込み用（320px） |
| `out/card_geometry.json` | カード内のmm寸法と、確定した行分割・文字サイズ |
| `out/proof_A4.pdf` | A4に55mm角と75mm角を並べた試し刷り |
| `out/editor.html` | 配置エディタ |

`card_geometry.json` を別に残しているのは、**入稿用PDFでは文字をベクタで組み直す**必要が
あるため。写真だけを埋め込み画像にして、タイトル・割合バー・凡例は同じ座標に
ベクタで置き直せば、版下と同じ絵が解像度非依存で得られる。

## カードの作り

一辺90mmの正方形に固定してある。ネットワーク図に88枚並べたときに高さがバラバラだと
配置が組めないため、タイトルは「2行に収まるまで12.5pt→9ptに縮める →
それでも入らなければ省略記号」で押し込んでいる（9件が縮小、最小10pt）。

- 上: サムネイル（3:2）。CALL4の画像は多くがタイトルを焼き込んだOG画像
- 中: ケース名（`【アーカイブ】` は削る。状況は枠の色と彩度で表す）
- 下: タグ割合の積み上げバー ＋ タグ名と割合の凡例

アーカイブは彩度を45%に落として枠をグレーにし、進行中を目立たせている。

## エディタでできること

- ドラッグで移動（複数選択・範囲選択）、1枚選択で右下の取っ手からサイズ変更
- カードサイズをmm指定（全体 / 選択のみ）、タグ文字サイズをpt指定
- 叩き台レイアウト5種（房状・放射状・Kamada–Kawai・力学・格子）。
  当てた直後に重なりを自動で解くので、押した時点で触れる状態になる
- 「整える（力学）」＝タグとの割合に応じたばねで全体を馴染ませる。
  ピン留めしたノードは動かないので、**要所だけ手で決めて残りは任せる**使い方ができる
- ズーム・パン、Undo/Redo、5mm吸着、カード画像↔点の切り替え（LOD）
- 保存/読込（JSON）、PNG書き出し（確認用）

### 自動点検（右パネル）

いまの配置に対して常時計算している。

- カード同士の重なり
- 印刷余白（25mm）の外に出ているカード
- **継ぎ目を跨いでいるカード** — 紙を2枚に分けて刷るなら物理的に貼れない
- タグラベルがカードに隠れている
- **配置サイズで300dpi / 200dpiを割るカード** — サムネイルの元解像度から個別に判定
- カードが占める紙面積（35%超で警告。エッジが見えなくなる目安）
- 配置サイズから逆算した実際の文字サイズ（タイトル / 凡例のpt）

叩き台5種はいずれも自動で「重なり0・紙外0・継ぎ目0・タグ埋没0」まで収束する。

## 未解決の点（エディタの上部にも同じものを表示している）

1. **タグ割合は暫定値**。タグ確認フェーズ1が終わるとカードの帯が変わる。
   位置はケースIDで保存するので配置作業は無駄にならないが、カード画像は作り直しになる
2. **タグ11色は画面用**。`#f032e6` `#3cb44b` `#00A0B0` はCMYK域外で必ずくすむ。
   色の差も縮むので、画面で見分けられたタグが紙では混ざる。
   印刷用の色を選び直し、実機で色校正を1回とる必要がある
3. **入稿用PDFが無い**。現状はCanvasなので拡大すると文字がボケる（上記の通りベクタで組み直す）
4. **実寸の試し刷りをまだしていない**。`out/proof_A4.pdf` をA4等倍で刷って、
   カードの文字が読めるサイズを手元で確かめる。カードサイズはその後に決まる
5. **継ぎ目なしで刷れるか未確認**。「A0×2 縦長」(841×2378mm) は914mm幅ロールに収まるので
   1枚で刷れる可能性がある。刷れるなら継ぎ目の制約が全部消える
6. **画像の権利**。CALL4掲載のサムネイルを含む図なので、公開物にするならCALL4の了解が前提

## 紙のサイズとカードの大きさ

A0 = 841×1189mm ≈ 1.0m²。88枚が紙面積の何割を占めるかで一辺が決まる
（エッジが見えるには25〜35%が上限）。

| 面積比 | A0 1枚 | A0 2枚 |
|---|---|---|
| 25% | 53mm角 | 75mm角 |
| 30% | 58mm角 | 83mm角 |
| 40% | 67mm角 | 95mm角 |

サムネイルの元解像度は最小1200px（一部に450〜1024pxが12件）。
75mm角に置くと7件が300dpiを、3件が200dpiを割る。最小のものは41mm相当。
この7件だけ小さく置くか、差し替え画像をもらうかの判断が必要。
